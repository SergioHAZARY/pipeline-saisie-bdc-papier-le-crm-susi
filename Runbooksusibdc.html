00

Lire le métier avant de toucher au code

2 heures · seul · aucun outil à installer

Tout le pipeline découle du manuel de saisie. Si vous démarrez la machine avant d'avoir lu ce document, vous ne saurez pas juger si une extraction est juste.

  1. Lire susi-bdc/manuel-commandes-rapides.md en entier, en particulier la page 16 : deux chèques, chèque absent → OA, contre-remboursement → OA, espèces → ne pas saisir.

  2. Retenir la grammaire des noms de fichiers, elle est utilisée partout :

    28082026FR_ATLAS_III_FID_50CH1.pdf
│        │  │          │   │
│        │  │          │   └─ 50 commandes, liasse n°1, avec chèque (OA = sans paiement)
│        │  │          └───── FID = client connu · RECRUT = nouveau client
│        │  └──────────────── campagne / support
│        └─────────────────── pays
└──────────────────────────── date du lot

    Et la règle de pagination du scan : pages impaires = chèques, pages paires = BDC.

  3. Parcourir ~/.claude/skills/susi-saisie-bdc/SKILL.md : c'est la spec de référence des 7 phases. Les prompts des jobs de la plateforme y renvoient — un écart entre l'app et le skill est toujours un bug de l'app.

Repère

Le dossier d'un lot est la seule source de vérité. Il n'y a pas de base de données : l'état affiché dans l'UI est recalculé depuis les fichiers par etat_lot(). Supprimer un fichier, c'est revenir en arrière dans le pipeline.

01

Monter la machine hôte

30 min · macOS obligatoire (Claude-in-Chrome + session SUSI)

  1. Récupérer le dépôt et les agents. Le code seul ne suffit pas — les trois agents et le skill vivent hors du dépôt :

    /Users/djisse/susi-bdc            # le dépôt
~/.claude/agents/bdc-lecteur.md
~/.claude/agents/susi-saisisseur.md
~/.claude/agents/susi-verificateur.md
~/.claude/skills/susi-saisie-bdc/ # la spec du pipeline

    Sur une autre machine que celle de Djibril, ces quatre chemins sont à copier tels quels.

  2. Installer poppler, utilisé pour le rendu des scans en 300 dpi :

    brew install poppler
pdftoppm -v          # doit répondre

  3. Connecter le CLI Claude Code — sans sudo, sinon la session s'installe dans le mauvais compte :

    claude /login
claude -p "ok" --output-format text   # doit répondre "ok"
02

Installer le pipeline et ses comptes

15 min · un seul fichier applicatif, app/app.py

  1. Créer app/.env (non versionné — demander les identifiants à Djibril plutôt que d'en inventer). Format :

    SUSI_BDC_UTILISATEURS=nom:mdp:role,nom2:mdp2:role2
# rôles disponibles : admin | viewer

    Si le fichier est vide, un compte admin est auto-généré au premier démarrage et affiché en console — le noter, il ne sera pas réaffiché.

  2. Vérifier que le dossier lots/ contient bien les deux lots de référence :

    LotContenuUsage
    29082026FR_ATLAS_III_FID_2CH94 pages · 2 commandesmini-lot de test, déjà extrait
    28082026FR_ATLAS_III_FID_50CH150 commandes · 2 396,58 €lot réel, extrait, en attente de revue
Ne pas toucher

Le lot 50CH1 est du réel : 50 vraies commandes et 50 vrais encaissements. Il sert de support d'apprentissage en lecture seule jusqu'à la phase 8.

03

Démarrer la plateforme

5 min · FastAPI sur le port 8760

  1. Lancer le serveur :

    /Users/djisse/susi-bdc/app/start.sh    # http://0.0.0.0:8760

  2. Si l'accès doit être partagé, ouvrir le tunnel — l'URL Cloudflare change à chaque lancement, ne la mettez pas dans un favori ni dans une doc :

    /Users/djisse/susi-bdc/app/tunnel.sh

  3. Se connecter (auth HTTP Basic, même schéma que la plateforme TLMC) et vérifier que les deux lots apparaissent avec le bon statut.

Symptôme connu

Un job qui reste bloqué en en_cours après un redémarrage n'est pas perdu : le verrou est en mémoire, l'orphelin se répare simplement en relançant le job.

04

Boucle à blanc sur le mini-lot

10 min · aucune interaction avec SUSI

Objectif : voir tourner extraction → revue → validation de bout en bout, et apprendre à lire un score avant de devoir en juger 50 d'affilée.

  1. Repartir de zéro sur 2CH9 en supprimant les sorties déjà présentes :

    extraits/*   lot.json   recap.md   jobs/*

  2. Lancer Extraction et suivre le log en direct (5 à 7 min) : vous devez voir la session s'ouvrir, les sous-agents partir, puis la consolidation.

  3. Ouvrir la Revue : deux commandes, avec leurs scores et leurs anomalies (chèque de tiers, case paiement non cochée…). Ouvrir une commande, comparer le scan affiché face au formulaire, corriger un champ, « Enregistrer ».

  4. Cliquer Valider le lot. validation.json apparaît et l'étape Saisie se déverrouille.

Lire un score de confiance

ScoreSignificationGeste
≥ 90OKsurvol rapide
70 – 89à vérifierrouvrir le scan sur les champs signalés
< 70review obligatoireressaisie manuelle du bloc

Le pré-saisie part de 100 et retranche : arithmétique lignes+frais ≠ total −40, chèque ≠ total −40, refco illisible −25, confiance basse/moyenne par article −20/−10, anomalies −5 chacune (plafond −20). Le post-saisie a son propre barème, appliqué par l'agent de vérification.

Arrêt de sécurité

S'arrêter ici tant que la première saisie supervisée n'a pas eu lieu. La bascule vers SUSI ne se fait pas seul, quel que soit le lot.

05

Préparer l'accès SUSI

20 min · avec Djibril · rien n'est encore saisi

  1. Activer le VPN AFM, puis ouvrir SUSI dans le Chrome de la machine : http://10.210.0.20/AFM/APP/SUSI/.

  2. Ouvrir la session applicative avec le login AA_AFM_100. C'est l'humain qui se connecte : les agents ne saisissent jamais d'identifiants ni de mot de passe, ils reprennent une session déjà ouverte.

  3. Vérifier l'intégration Chrome de Claude (outils claude-in-chrome) sur cet onglet.

  4. Faire à la main, humainement, une commande dans « Saisie commande rapide » — F5 créer un lot, TAB entre champs, F4 bloc suivant, Echap clôturer — pour confirmer que les raccourcis du manuel correspondent bien à l'UI réelle. C'est exactement ce que l'agent n'a jamais vu.

06

Première saisie supervisée

Le moment critique · mini-lot 2CH9 · main sur l'échappement

On lance susi-saisisseur sur les 2 commandes du mini-lot, en regardant l'écran champ par champ. Un seul exemplaire de l'agent, jamais deux en parallèle.

  • VPN actif, session SUSI ouverte dans Chrome, bon utilisateur
  • Lot validé : validation.json présent
  • Un seul susi-saisisseur lancé, aucune autre session Claude sur SUSI
  • Djibril présent, écran partagé, prêt à interrompre
  • saisie.log.json ouvert en parallèle pour suivre la reprise

  1. Lancer la Saisie depuis l'app — ou, en session Claude Code, glisser le PDF du lot et dire « traite mes bdc » : le skill susi-saisie-bdc se déclenche et écrit le même état sur disque.

  2. Regarder la première commande en entier sans rien faire d'autre. Vérifier l'ordre des champs, le comportement de F4, la clôture.

  3. Interrompre au moindre écart et noter ce qui diffère du manuel. Ces écarts sont la matière de la mise à jour de susi-saisisseur.md — le manuel est théorique, l'UI est la vérité.

  4. Laisser passer la seconde commande, puis mettre à jour la passation : l'état « jamais exécuté » n'est plus vrai.

Contraintes de la plateforme

SUSI supporte environ 80 à 100 requêtes puis renvoie des HTTP 500, et les sessions expirent sous charge. D'où la règle : un seul job à la fois, verrou global, saisie strictement séquentielle.

07

Vérification post-saisie

Toujours sur le mini-lot, avant d'aller plus loin

  1. Lancer susi-verificateur : lecture seule, il compare le rapport Excel SUSI et le détail UI au scan d'origine — jamais au JSON d'extraction, sinon une erreur de lecture se confirmerait elle-même.

  2. Ouvrir verification.json / review.md, trié par score croissant. Barème : écart montant −40, article faux −25, mauvais client −30, commande absente ou en double = 0.

  3. Traiter les commandes en tête de liste dans SUSI, à la main.

08

Passer le lot réel 50CH1

50 commandes · 2 396,58 € · uniquement après un mini-lot propre

  1. Revue complète des 50 commandes. Compter environ 16 min d'extraction déjà faites ; la revue est le poste humain le plus long.

  2. Écarter explicitement la commande 26 : c'est un double passage scanner (même chèque CMC7, même BDC que la paire voisine), pas une seconde commande.

  3. Contrôler les doublons restants sur les lignes CMC7 et les n° clients avant de valider — le contrôle est aujourd'hui fait par l'agent, pas encore de façon déterministe.

  4. Recroiser les refco extraites avec le référentiel (atlasformen.fr ou export SUSI). Cas déjà vu : KB179 lu pour K8179.

  5. Valider, saisir, vérifier — dans cet ordre, sans jamais paralléliser.

Les erreurs métier à traquer en revue

  • Sur un chèque, les lettres font foi pour le montant ; sur un BDC, le total se recalcule depuis les lignes.
  • Confusions manuscrites classiques : 0/O, 1/1, 2/2, 5/5, B/8 sur les refco.
  • Scans à 180° — le rendu peut être à l'envers sans que le score s'en aperçoive.
  • Cas manuel p. 16 : deux chèques, chèque absent → OA, contre-remboursement → OA, espèces → ne pas saisir.
09

Durcir avant d'en faire de la production

Après le premier run réussi, dans cet ordre de priorité

  1. Systématiser la validation des refco au catalogue dès l'extraction, dans la phase 3 ou dans l'app.

  2. Détection de doublons déterministe dans score_extraction() / la consolidation : comparer lignes CMC7 et n° clients entre commandes d'un lot.

  3. Plateforme : comptes nominatifs par membre, tunnel stable (Cloudflare nommé ou Tailscale à la place de l'éphémère), file de jobs persistante pour que le verrou survive à un restart.

  4. Tests : rien n'est couvert. Commencer par score_extraction(), le parsing de nom de lot (RX_NOM) et _lignes_lisibles().

Pièges déjà payés — ne pas les réapprendre

  • stdin=subprocess.DEVNULL est obligatoire sur le claude -p du job runner, sinon il hérite du stdin d'uvicorn et se fige (constaté : 3 h à 0 % CPU).
  • Épurer l'environnement avant de lancer claude -p depuis un process lancé par une session Claude (regex CLAUDE|ANTHROPIC|BAGGAGE|AI_AGENT|SENTRY) : les variables héritées court-circuitent l'auth → 401.
  • --mcp-config exige {"mcpServers": {}}, pas {}. L'extraction tourne en --strict-mcp-config ; la saisie garde la config par défaut, il lui faut claude-in-chrome.
  • --output-format stream-json --verbose + parsing ligne à ligne pour un log visible en direct ; en text, rien ne sort avant la fin.
  • pdftoppm adapte le zéro-padding au nombre de pages : renommer systématiquement en p_NNN.jpg, sinon le tri lexicographique casse.
